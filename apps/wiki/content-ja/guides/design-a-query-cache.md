クエリキャッシュは、ウェブサーバーと検索バックエンドの間に置かれ、繰り返しの検索をメモリから返します。正規化したクエリをキーにし、最も長く使われていないエントリを追い出し、結果が長く古いままにならないよう各エントリを短い TTL で期限切れにします。1 つのノードがホットな集合を持ちきれないときは、ハッシュでキーを複数のキャッシュノードに分けます。

これは [System Design Primer](https://github.com/donnemartin/system-design-primer) の問題の 1 つで、その[クエリキャッシュの解答](https://github.com/donnemartin/system-design-primer/blob/master/solutions/system_design/query_cache/README.md)はこのページと並べて読む価値があります。

## 要件

機能要件:

- 最近見られた検索は、キャッシュから返る。
- 見られていない検索はバックエンドへ行き、答えが保存される。
- 人気のクエリはキャッシュに残り、まれなものは落ちてもよい。

非機能要件:

- 検索は約 1 ミリ秒なので、キャッシュはメモリ上に置く必要がある。
- キャッシュノードが死んでもサービスは動き続ける。キャッシュを外すと遅くなるが、エラーにはならない。
- 結果は数分古くてもよいが、削除されたページが何時間も表示されてはいけない。

## 負荷を見積もる

検索は月 100 億件、1 か月は 250 万秒とします。

- 平均レート: 10B / 2.5M より毎秒 4,000 件の検索です。平均の 3 倍のピークは 12,000 です。
- トラフィックには偏りがあります。5,000 万の異なるクエリが検索の 90% を占め、残りは 1 回きりとします。
- エントリのサイズ: 正規化したクエリは約 50 バイト、10 件のタイトルとスニペットのページは約 2 KB です。したがって 50M のエントリは約 100 GB です。
- バックエンドの負荷: ヒット率 90% なら、バックエンドはピークの 12,000 の 10%、つまり毎秒 1,200 を受けます。ヒット率を 95% に上げると 600 になります。

Redis の 1 ノードは数十ギガバイトを無理なく持てるので、100 GB なら 4 か 5 ノードです。メモリの請求よりも、バックエンドの節約のほうが大きく効きます。

## 設計

### クエリの正規化

どの検索よりも前に、クエリ API はテキストを小文字にし、マークアップを取り除き、空白を削り、明らかな誤字を直します。「Cheap Flights NYC」と「cheap flights nyc 」は同じキーに当たるべきです。まとめたクエリが増えるたびに、ヒット率はただで上がります。

### キャッシュ

クエリ API は、Redis や Memcached のようなメモリストアを確認します。ヒットならすぐ返します。ミスなら検索バックエンドに問い合わせ、結果をキーの下に書いて返します。これが[キャッシュアサイド](/patterns/cache-aside)で、ロジックはアプリケーションが持ちます。キャッシュノードが落ちていれば、呼び出しはバックエンドへ素通りします。

### LRU による追い出し

メモリには限りがあるので、キャッシュは最も長く触られていないエントリを捨てます。古典的な作りは、キーからダブルリンクリストのノードへのハッシュマップです。読み取りはそのノードを先頭に動かし、満杯での挿入は末尾を取り除きます。どちらの操作も一定時間です。Redis は数個のキーをサンプリングしてこれを近似します。そのほうが安く、十分に近いからです。

### TTL と無効化

検索結果は、ページが変わったりランクが動いたりすると変わりますが、キャッシュにはそれが分かりません。各エントリに数分の TTL を付けます。人気のクエリはよく期限が切れるのでよく更新され、まれなものはほとんど問題になりません。削除要請のような緊急の取り下げには、対象のキーに対する削除を発行します。

### キャッシュのシャーディング

クエリのキーをハッシュして、N 個のノードの 1 つに送ります。単純な剰余は N が変わるとほぼすべてを入れ替えるので、キーの約 1/N しか動かさない[コンシステントハッシュ](/patterns/consistent-hashing)を使います。一般的な場合は[シャーディング](/patterns/sharding)を参照してください。1 つのノードのキーを失うとバックエンドが溺れるなら、各シャードの後ろにレプリカを置きます。

## どこで壊れるか

**人気のエントリが期限切れになる。** 同じ流行のクエリに対する 1 万件のリクエストが一斉にミスし、すべてバックエンドに当たります。1 つのリクエストにエントリを作り直させ、ほかは待つか古いコピーを取るようにし、TTL にジッターを加えます。[キャッシュスタンピードの保護](/patterns/cache-stampede-protection)を参照してください。

**コールドキャッシュ。** 再起動やデプロイのあとは、ヒット率がゼロで、バックエンドが全負荷を受けます。トラフィックを流す前に、前日の上位クエリでキャッシュを温めます。[キャッシュウォーミングと階層キャッシュ](/patterns/cache-warming-and-tiered-caching)を参照してください。

**ホットシャード。** 有名人のクエリ 1 つは、1 つのノード上の 1 つのキーです。ホットなキーを複製するか、各クエリ API サーバーに小さなローカルキャッシュを持たせます。[ホットキーとホットシャード](/patterns/hot-keys-and-hot-shards)を参照してください。

**追い出しの乱高下。** クローラーが数百万の一意なクエリを歩き回り、本当にホットなエントリを押し出します。1 回しか見られていないクエリはキャッシュしません。

## Quorum で作る

最初の設計は、読み取りの経路を示します。[データベース](/components/database)の前に[キャッシュ](/components/cache)を置き、キャッシュの既定の戦略は、TTL とサイズを持つキャッシュアサイドです。ヒット率が上がるにつれてデータベースの負荷が下がる様子を見てください。

::Design{id="cache-aside"}

2 つ目の設計は、キャッシュで 2 つのスタンピード対策をオンにしたもので、人気のエントリの問題への答えです。そのキャプションを、[キャッシュスタンピードの保護](/patterns/cache-stampede-protection)にある対策なしの版と比べてください。

::Design{id="stampede-guarded"}

3 つ目の設計は、複数のシャードとハッシュキーを持つデータベースです。ゲームではシャードはキャッシュノードではなくデータベースですが、キーの散らばりへの効果は、キャッシュで説明するものと同じです。キーの選び方が何をするかは[シャーディング](/patterns/sharding)を参照してください。

::Design{id="sharded-hash-key"}

最後の設計は、データベースの隣に[検索エンジン](/components/search)を置きます。ゲームの中で、キャッシュの背後にあるバックエンドにいちばん近いものです。

::Design{id="search-engine"}

[キャッシュ](/research/caching)と[スタンピード対策](/research/stampede-protection)をリサーチして、スイッチをアンロックします。[キャッシュスタンピード](/incidents/stampede)のインシデントはコールドスタートの場合を試し、[スタンピード](/sandboxes/stampede)のサンドボックスでは自分で実行できます。

ゲームには、LRU リストも、クエリの正規化も、キーごとの無効化も、コンシステントハッシュのリングもありません。キャッシュにあるのは個々のエントリではなく、サイズとヒット率です。

## よくある質問

### LRU キャッシュはどう動きますか?

ハッシュマップとダブルリンクリストを組み合わせます。検索はマップでノードを見つけてリストの先頭に動かし、キャッシュが満杯のときは末尾のノードを取り除きます。どちらの手順も一定時間です。

### 検索クエリのキャッシュはどう無効化しますか?

たいていはしません。数分の短い TTL で各エントリが自然に期限切れになり、これは単純で、順位付きの結果には十分です。緊急の場合は、変更が公開されたときに特定のキーを削除します。

### キャッシュをサーバー間でシャーディングするには?

キーをハッシュしてノードに対応づけます。ノードを足しても動くキーがわずかで済むよう、コンシステントハッシュが望ましいです。ルーティングはクライアントか、Twemproxy のようなプロキシが行います。

### System Design Primer はクエリキャッシュについて何と言っていますか?

Primer は、キャッシュヒット、キャッシュミス、高可用性に範囲を絞り、ハッシュテーブルとリンクリストで作った LRU キャッシュを使います。このページは同じ範囲を扱い、シャーディングとスタンピードの場合を加えます。
